## 2. 页面结构（5 大区）

### ① 对比概览区
每商品一张卡片：合格图片（走现有 `ProductImage` 授权门控 + 空态）、完整名称、品牌·品类、当前价（"模拟报价"标注）、性价比分数+等级（S/A/B/C/D）、用户评分、核心配置摘要（前 3 项参数）、**与最低价差额+百分比**、优势标签（价格最低/性价比最高/某参数更强，来自方向明确参数的实测对比）、图片署名（作者·许可·来源·许可链接）、商品详情/移除按钮。

### ② 核心差异分析
从分组参数中取前 6 个关键键，逐项对比输出"【参数】A：v1；B：v2"事实型差异条目 + 价格差异条目；参数缺失的键单独提示"以下参数存在数据缺失"。无共有数据时显示"数据不足，暂无法给出可靠对比结论"，**不生成虚假分析**。

### ③ 核心规格横向对比（分组式）
- **按真实 `product_specs` 键设计 16 个分类各自的参数组**（手机/平板/笔记本/台式/显示器/耳机/键盘/鼠标/相机/手表/游戏机/显卡/CPU/SSD/内存/路由器），中英文键（`chip`/`处理器` 等）归一化到统一标签。
- 分组展示（性能/屏幕/影像/续舱…），全员缺失的键不展示，缺失值显示"暂无数据"。
- **只看差异开关**：过滤掉所有商品取值一致的行（实测 13 行 → 8 行）。
- **更优值高亮**：仅对方向明确的可量化参数（电池/刷新率/读取速度/频率等 ↑，重量/TDP/时序 ↓），需全部商品有可解析数字才判定，**不简单比较大小**。

### ④ 价格与性价比分析
当前价、与最低价差额+百分比、性价比分数+等级、性能分数、用户评分、参数完整度、**多平台最低报价**（实时调 `/api/prices/compare/{id}`）、**模拟历史最低/最高**（`/api/prices/history/{id}`）、**90 天价格走势 echarts 折线图**（每商品一条线）。
- 全区顶部挂"模拟数据，非实时电商价格"徽标，底部再次声明"不代表任何平台真实成交价"；图表标题标注"模拟数据"。
- **"多花的钱能换来什么"**：逐商品对比最低价商品，列出贵出价格 + 可量化的配置优势（或明示"配置数据未体现明显优势"）+ 性价比分差。

### ⑤ 怎么选
4 张推荐卡（性价比优先/性能优先/预算优先/综合推荐），每卡含：推荐商品、理由（引用实际分数与价格）、牺牲/不足、适合人群（按分类映射）、结论可信度。
- 分数打平时输出"当前数据不足，暂无法给出可靠排名"，**不强行选冠军**。
- 综合推荐 = 性价比 50% + 性能 30% + 参数完整度 20%（归一化加权），推荐依据透明。
- 所有推荐随实际选择商品动态计算，无任何硬编码商品名。

## 3. 数据来源与缺口

| 数据 | 来源 | 状态 |
|---|---|---|
| 规格参数 | `/api/products/{id}` 的 `specs`（product_specs 表） | **缺口**：规格为模板生成的中英文键值对（如 `chip`/`处理器`），非官方参数；部分老商品规格键不同（如游戏机用 `type/特性`） |
| 多平台报价 | `/api/prices/compare/{id}`（product_prices 表） | 完整，全部标注"模拟报价" |
| 历史价格 | `/api/prices/history/{id}`（price_history 表，`source=SIMULATED/mock`） | 完整 90 天，全部标注"模拟数据" |
| 性价比/性能分数 | 商品实体字段（系统模拟评分） | 可解释性弱——已在推荐卡"可信度"中声明"基于现有模拟评分，无实测跑分" |
| 发布时间 | `launchDate`（多数为通用值） | 未在页面主打展示 |

## 4. 保留的既有业务规则

- 同品类限制（store 前端拦截 + Service 后端拦截）——浏览器实测：手机+鼠标 API 返回 400"商品规格对比仅支持同一品类"
- 最多 4 个商品、重复添加拦截、图片授权门控（`ProductImage` 组件 + 空态）
- 跨平台比价（`PriceController`）独立未动；Mock 数据源/同步/授权业务零改动

## 6. 未解决的问题

1. **规格数据质量**：`product_specs` 为模板生成（不同批次键名不统一：`chip` vs `处理器`），对比表已做键归一化，但深层数据仍非官方参数——需要官方规格需人工补充数据库。
2. **性价比分数可解释性弱**：分数为系统模拟值，页面如实标注可信度，未修改评分算法（按任务要求）。
3. **"更换商品"为跳转商品列表**（沿用现有交互），未做弹窗内商品选择器。
4. **移动端适配为基础方案**（栅格自适应 + 表格横向滚动），未做深度移动优化。
