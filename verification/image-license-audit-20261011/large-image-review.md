## 二、处理建议

### 2.1 首选：Wikimedia 官方缩略图 URL（合法、稳定）

- `upload.wikimedia.org/wikipedia/commons/thumb/<a>/<ab>/<File>/<W>px-<File>` 是 Commons **官方缩略图服务**，API 的 `iiurlwidth` 参数即返回该 URL（阶段 B-1 的 14 张缩略图均来自此机制）。
- 许可角度：缩放是纯机械调整，CC BY/BY-SA 不视为产生新义务（保留署名即可）。
- 稳定性：热链长期可用是实践共识，但**非合同承诺**——建议授权记录中同时保存 originalUrl 与 displayUrl 两个字段（方案 B 的 license 表可加 `original_url` 列），一旦缩略图失效可回退原图。
- **注意**：入库 URL 应去掉 `?utm_source=...` 跟踪参数（当前 14 张缩略图 URL 带 utm，见审计 riskNotes），纯路径更稳定也更干净。

### 2.2 自建衍生图托管（需谨慎）

- 可行但有代价：**CC BY-SA 图片的衍生作品需同许可共享**（ShareAlike 义务延伸到衍生图）；若自建 CDN 托管衍生图，等于本站承担了 BY-SA 的分发义务。
- CC BY / CC0 图片无 ShareAlike 义务，自建衍生风险低。
- 结论：**优先用官方缩略图**；只有当 Commons 缩略图不可用时再考虑自建，且仅限 CC BY/CC0 图。

### 2.3 前端兜底（已具备）
- `ProductImage.vue` 已有加载失败自动回退类别 SVG 的能力，大图加载慢不会破图，但会拖慢首屏——这是推动换缩略图的直接动力（首页 8 张原图实测需约 15 秒全部解码）。

## 三、防丢失原则（换 URL 时的铁律）

1. 换 URL **只改 `product_images.url` 的展示地址**，授权证据（source_page_url / original_url / license）全部保留在授权表——**原始页面永远是核验入口**。
2. 换图与换 URL 分开处理：换 URL 是数据更新（阶段 B-2 执行时用事务 + 备份）；换图（REJECTED 的 5 张）是新候选走完整审核。
3. 禁止"先换后补授权"：任何 URL 变更必须与授权记录同事务更新。
